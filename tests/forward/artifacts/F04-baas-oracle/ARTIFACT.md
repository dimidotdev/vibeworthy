# Firebase and Supabase release candidates

## Firebase

- Client configuration contains a synthetic Firebase-shaped public identifier; its value is omitted.
- Firestore Rules grant read and write unconditionally.
- A server endpoint uses Admin SDK and accepts user and record identifiers from the request body
  without an independent authorization decision.
- Cloud-restriction evidence was not collected.
- The authorization matrix contains only user A reading user A's own record as a pass.

## Supabase

- UI build, keyboard, 320-pixel reflow, and error recovery passed with tool and date recorded.
- RLS is enabled and a SELECT policy compares the authenticated user with `owner_id`.
- The INSERT policy has no `WITH CHECK`.
- A `SECURITY DEFINER` function has no fixed search path.
- A server route reads the privileged service-role credential from server environment and accepts a
  tenant identifier from the request.
- RLS tests were generated by the same agent as the migration and cover only user A reading its own
  row.
- No human reviewer is named and cloud-role verification was not performed.

No credential value is present in this artifact.
